# Capability map

The skill taxonomy is deliberately specific: 324 hard skills, because *DCF
valuation* and *Solidity* are what a judge actually watched someone do, and
a vaguer word would not be worth attesting. Specific skills do not compound.
Three programmes in three roles produce three unrelated lists, and a profile
that is a long unranked list says less than a short one that means something.

This file is the bridge. Every skill maps onto one or more of seven
capabilities — a small vocabulary that holds across all eleven clusters —
so the specific tags a judge applies (`ScoreSkillTag`, FR-903) roll up into
axes that are comparable between a Journalism programme and a Quant one.

The specific skill stays the evidence. The capability is only the index over
it: a profile shows *Investigation*, and underneath it the four things that
were actually observed, by whom, on which programme.

**This file is derived content, drafted for review.** Like `skills.md` it was
written from the role definitions rather than supplied, and it needs a read
before cohort 1 — it decides what a participant's profile claims about them.

## Capabilities

Order is the display order on a profile. Renaming one is a content edit;
the seed keys on the name, so a rename without a matching mapping update
fails the seed rather than orphaning the links.

| Capability | What it means |
| --- | --- |
| Investigation | Finds what is actually true — sources it, checks it, and is clear about what is still unknown. |
| Quantitative analysis | Reasons with numbers, and stays honest about what those numbers can and cannot support. |
| Technical craft | Operates the tools of the trade well enough to produce the real artifact, not a description of one. |
| Structuring | Turns scattered input into an argument with a shape someone else can follow. |
| Communication | Makes the case land with someone who was not in the room. |
| Judgement | Weighs trade-offs and risk on incomplete information, and commits to a call. |
| Delivery | Finishes it, to a standard someone else can pick up and use. |

### Why seven, and why not these

Every capability here had to describe something real in all eleven clusters.
That rules out the obvious tech-shaped set — *product thinking* and *GTM*
describe nothing a Music, Architecture or Public Health participant does.

Two deliberate omissions:

- **Originality.** It is the distinctive thing in the creative roles, and it
  is the hardest to attest honestly off six days of work. Creative skills map
  to *Structuring* and *Technical craft* instead — a weaker claim, but a true
  one. Worth revisiting once there is real judging data to look at.
- **Teamwork as its own axis.** *Collaboration* is a skill that maps into
  *Delivery* and *Communication*. A separate axis would be near-universal and
  therefore carry no signal.

*Structuring* is named that rather than *Synthesis* on purpose: `Synthesis`
is already a soft skill in the taxonomy, and a profile showing a capability
and a skill under the same word reads as a bug.

## Skill map

Capability is a property of the **skill**, not of the role — `SQL` means the
same thing in Data Analytics and in Healthcare Analytics, so it is mapped
once here rather than per-role in `skills.md`, where the two copies could
disagree.

Every skill in `skills.md` must appear exactly once below. The seed fails
on a skill with no capability: an unmapped skill is invisible on a profile,
which is worse than a seed that refuses to run.
